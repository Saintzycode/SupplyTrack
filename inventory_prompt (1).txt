Tables (PK = primary key, FK = foreign key):

Relationships: categories 1-M items; items M-M suppliers (via item_suppliers); items 1-M stock_transactions; schools 1-M distributions; distributions 1-M distribution_items; items 1-M distribution_items; users 1-M stock_transactions, distributions, audit_logs; items 1-M low_stock_alerts.

Database triggers already handle these rules (do not duplicate them in PHP):
- BEFORE INSERT on stock_transactions: rejects inactive items, rejects any change that would make stock negative (SQLSTATE 45000 with a readable message), and sets quantity_after.
- AFTER INSERT on stock_transactions: updates items.quantity_on_hand, creates a low_stock_alerts row when quantity <= reorder_point, and resolves open alerts when quantity goes back above it.
- UPDATE and DELETE on stock_transactions are blocked (non-editable audit trail).
- AFTER INSERT on distribution_items: automatically inserts a stock_out row into stock_transactions (negative quantity_change, linked by distribution_item_id).

Views already available:
- v_stock_status (FR-7.2), v_stock_transaction_report (FR-7.3), v_distribution_report (FR-7.4, FR-5.3, FR-6.4), v_dashboard_summary (FR-7.1).

PHP coding rules:

- Handle login lockout (5 failed attempts using failed_attempts and locked_until) and the 30-minute inactivity logout in PHP.
- Write to audit_logs from PHP for create/update/delete/login/password-reset actions.
- Check the user's role on every admin-only page (not only in the menu).
- Keep code modular (config, db connection, models/functions, views) and copy-paste ready with file names.
